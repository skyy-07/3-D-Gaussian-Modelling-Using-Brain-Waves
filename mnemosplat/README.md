# MnemoSplat

**Same words. Different memory.**

MnemoSplat turns a spoken episodic memory into a WebXR 3D Gaussian volume whose
*density, opacity and spread* are conditioned by posterior EEG salience. The language
model decides **what** is in the room; monocular depth decides **where** it is; EEG
decides **how vividly it consolidated**. EEG never touches an RGB pixel.

The demo ships two conditions built from **one transcript, one scene graph, one
keyframe and one depth map**. The only variable between them is the neural channel.

```text
transcript ──► Muse Spark ──► scene graph (entities, boxes, beats)
                                   │
                                   ├──► Muse Image ──► keyframe ──► DA-V2 depth
                                   │                                  │
posterior EEG ──► Welch PSD ──► salience + attention field M(u,v) ────┤
                                                                      ▼
                                                single-view Gaussian lift (gsplat-compatible)
                                                                      │
                                                         .splat / .ply + manifest.json
                                                                      │
                                                         WebXR (GaussianSplats3D)
```

## Quickstart (CPU only, no keys, no GPU)

Requirements: Python ≥ 3.10, Node ≥ 20.

```bash
cd mnemosplat
python -m venv .venv                 # or: uv venv .venv
. .venv/bin/activate
uv pip install -e ".[dev]"           # pip install -e ".[dev]" also works

# 1. Generate the paired demo (≈60 s on a laptop CPU, cached afterwards)
mnemosplat demo --scenario both --out out/demo --splats 120000 --force

# 2. Build the WebXR client once
cd web && npm install && npm run build && cd ..

# 3. Serve API + client + assets on one origin
mnemosplat serve --host 0.0.0.0 --port 8000
```

Open <http://127.0.0.1:8000>. First load lifts the first volume; the HUD then shows
neural salience, band power, entity ranking, provenance, and the consolidation
timeline.

Useful checks:

```bash
mnemosplat doctor                 # capability report; add --probe to call GET /models
mnemosplat selftest               # tiny 256 px episode, CPU only
mnemosplat export out/demo/focus/frames/000.splat /tmp/frame.ply
python -m pytest -q               # 74 tests
ruff check src tests
```

`out/demo` is generated by step 1 and ignored by Git. Once it exists, `serve` works
without regenerating anything; the Docker image performs the same step at build time.

## Deploy on Render

The repository includes a multi-stage `Dockerfile` and a Render Blueprint. The image
builds the Vite client, installs the Python package, and generates the offline
focus/distracted assets **at build time**; runtime needs no GPU or API key. The only
runtime writes are ephemeral recorded-EEG uploads under `/app/out/demo/live`.
Use the Docker runtime (not Render's native Python runtime): the assets are produced
inside the image, and `out/` is intentionally not committed.

If the repository root contains `mnemosplat/`, use the parent `render.yaml`. If
`mnemosplat/` is the repository root, use `mnemosplat/render.yaml`.

1. Push the repository to GitHub.
2. In Render: **New → Blueprint**, select the repo, apply the detected `render.yaml`.
3. Leave `MODEL_API_KEY` and `MNS_ADMIN_TOKEN` empty for the static demo; paid generation stays blocked, but recorded EEG uploads remain available.
4. Open the HTTPS service URL. WebXR on Quest needs that secure context.

`MNS_PUBLIC_DEMO=1` blocks the paid generation endpoints with `403` unless an
`MNS_ADMIN_TOKEN` is configured and supplied as `X-MNS-Token`; the paid generation
path only reads the baked assets. `POST /api/eeg` remains public because it is CPU-only
and never calls a paid model. Health check: `/api/health`. Free-plan services spin
down when idle, so the first request can take 30–60 seconds; an uploaded re-lift can
take a minute or more on the free CPU allocation.

Full instructions, environment variables, verification commands, and troubleshooting:
[docs/DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md).

> Docker was not installed in the development environment used to prepare this
> checkout, so the image was validated by running its build steps and a production-mode
> server locally, not by a local `docker build`. The first Render build log is the
> authoritative image check.

## The demo in 90 seconds

1. **Boot screen** — "A spoken memory becomes a 3D Gaussian volume. EEG salience
   decides how vividly it consolidates — never what it looks like."
2. **Vivid recall** — salience ≈ 0.50 mean / 0.67 peak. The mug, notebook and window
   are tight and opaque. Orbit slightly; the room has parallax.
3. **Switch condition (`D`)** — the same room, same camera, same keyframe. The volume
   becomes wide, translucent fog. Salience ≈ 0.18 mean / 0.25 peak.
4. **Scrub the timeline (`←` / `→`)** — each epoch re-lifts the *same* keyframe with a
   different attention field. Consolidation changes, camera motion does not.
5. **Open “?”** — the method, the control, and the provenance chips: synthetic EEG,
   procedural or Muse keyframe, offline or Meta scene graph, depth source.
6. **Enter VR** (Quest) — the manifest camera is mapped to the headset origin. Trigger
   advances an epoch, squeeze goes back, the DOM overlay shows condition and salience.

Keyboard: `←/→` epoch, `Space` play, `F`/`D` condition, `1`/`2` condition, `R`
recentre, `H` hide HUD, `A` salience field, `Esc` close.

## Bring your own recorded EEG

The public demo has an **Upload EEG** button. It accepts a recording, analyses the
posterior bands, and re-lifts the *already baked* keyframe and depth map with the
recorded salience. The uploaded recording is labelled **recorded EEG** in the HUD,
the provenance chips and `manifest.upstream`; the original focus/distracted pair stays
labelled **synthetic EEG**.

What changes: density, opacity, Gaussian covariance and sampling. What does not
change: transcript, scene graph, keyframe RGB pixels, depth map, or the camera model
(FOV/intrinsics). The viewer keeps its existing framing when you switch conditions.

### Accepted files

| Format | Contract |
| --- | --- |
| `.csv`, `.tsv`, `.txt` | Header row recommended, one row per sample. Channels are named (`O1`, `EEG O2`, `Pz`, ...). An optional time column (`time`, `timestamp`, `seconds`, `time_ms`, ...) is removed and used to infer the sampling rate. |
| `.npy` | A 2-D numeric array, either `(channels, samples)` or `(samples, channels)`. NumPy files carry no rate or channel labels, so enter the sampling rate; generic channel names are used. |

`EDF`/`BDF`/EEGLAB/BrainVision are rejected with an export hint rather than adding a
heavy reader to the public deployment. Export CSV or NPY for now.

Example CSV:

```csv
time,O1,O2,Oz,P3,P4,Pz
0.000,12.4,-8.1,3.2,5.4,-1.2,0.4
0.004,11.9,-7.6,3.8,4.9,-0.8,0.1
...
```

### Limits and behaviour

- **Length:** at least three 0.75 s windows (2.25 s). Longer recordings are analysed
  in full and reduced to the four narrative beats. At least 100 Hz and at most 2000 Hz;
  gamma needs a Nyquist frequency above 45 Hz.
- **Size:** 12 MB per file, at most 32 channels and 3,000,000 parsed values.
- **Public budget:** one re-lift at a time, four uploads per 15 minutes per address,
  and a lower default splat budget (`MNS_EEG_TARGET_SPLATS=60000`) than the baked
  120k demo. All defaults are environment-overridable; see `GET /api/health`.
- **Cost:** the upload path never calls Muse Spark, Muse Image, SAM, Voice Transcribe,
  or any paid endpoint. It also sets the Meta client key to empty as a hard guard.
- **Storage:** uploads are written to `MNS_OUT/live/eeg-<id>/` and are **ephemeral**.
  They disappear on a service restart or redeploy. The UI keeps at most two uploaded
  conditions in the current session; the server keeps four completed jobs.
- **Privacy:** files are processed in memory and are not written outside the service's
  temporary asset directory. Do not upload clinical or identifiable data to a public
  demo. No diagnosis is made.

### API

```bash
curl -fsS -X POST https://YOUR-SERVICE.onrender.com/api/eeg \
  -F "file=@recording.csv" \
  -F "sfreq=250"

# {"job":"<id>","state":"queued","key":"eeg-<id>"}

curl -fsS https://YOUR-SERVICE.onrender.com/api/eeg/jobs/<id>
```

The job progresses through `queued → analyzing → lifting → done` (or `error`). On
success, `scenario.manifest` is a path under `/assets/live/eeg-<id>/manifest.json`;
the client adds it as a condition automatically. The keyframe is pixel-identical to
the baked base episode and the depth array is unchanged; the upload manifest records
the source filename, analysed window count, beat count, sampling rate and channel
count.

## Why this architecture

### EEG as a low-dimensional gate, not an image generator

Every EEG-to-image project is tempted to regress pixels. The signal-to-noise ratio is
not there, and a bad reconstruction is indistinguishable from a bad model. MnemoSplat
uses EEG for the thing posterior gamma/theta actually indexes well: **how strongly a
memory was encoded**, plus a weak hemifield prior from O1/O2 asymmetry. That scalar
modulates opacity, covariance and sampling density. The language model supplies
semantics; depth supplies geometry.

### One keyframe, many epochs

The timeline scrubs *consolidation*, not camera motion. One keyframe per episode means:

- geometry never tears between frames (the classic fake-looking splat demo);
- Muse Image is called once per memory (`$0.01` list price at build time), not once
  per timeline frame;
- the only thing that changes across the slider is exactly what we claim EEG controls.

`PipelineConfig(per_beat_keyframes=True)` exists for the experimental multi-keyframe
mode, but it is not the demo path.

### Paired conditions as the control

`run_pair()` renders focus and distracted from one narrative. The second condition
receives the first condition's **serialised scene graph, keyframe PNG and depth
array**. The manifests record this explicitly:

```json
"upstream": {
  "scene_graph": "shared:paired-condition",
  "keyframe": "shared between conditions",
  "depth": "shared"
}
```

A judge can diff the two `scene_graph.objects` arrays and the keyframe bytes.

### Graceful degradation is a feature

No key, no GPU, no model download, no checkpoint: the pipeline still produces a
complete episode. Every fallback is named in `manifest.upstream`; nothing pretends a
model ran when it did not. `BrainVisSalienceEncoder` raises rather than emitting
untrained pseudo-salience.

## Meta surface used

| Model | Role | Code | Fallback |
| --- | --- | --- | --- |
| `muse-spark-1.3` | Transcript → entities, boxes, depth hints, beats | `mns.director.meta_client.chat_json` | Keyword recipes (`mns.director.recipes`) |
| `muse-image-1.0` | One photographic keyframe per episode | `mns.render.muse_keyframe` | Procedural scene-graph renderer |
| `sam-3.1` | Boxes → masks over the keyframe | `mns.director.scene_graph.refine_with_sam` | Exact recipe masks / soft boxes |
| `muse-voice-transcribe-1.0` | Spoken memory → transcript | `mns.director.meta_client.transcript_from_audio` | Typed transcript |
| `muse-wonder-1.0` | Optional harder narratives | configurable model id | same as above |

Base URL `https://api.meta.ai/v1`, bearer auth from `MODEL_API_KEY`. The retired
`api.llama.com` preview is deliberately not used. Details and request shapes:
[docs/META_INTEGRATION.md](docs/META_INTEGRATION.md).

## WebXR / Quest

The client is Vite + three.js 0.170 + `@mkkellogg/gaussian-splats-3d` 0.4.7.

- `webXRMode: VR`, reference space `local`: the headset origin is the manifest camera,
  so the room appears at the viewpoint it was lifted from.
- The splat scene is translated by `-camera_position` instead of moving the eye. Desktop
  orbit and headset position therefore agree.
- Trigger = next epoch, squeeze = previous.
- COOP/COEP headers are set by both FastAPI and Vite so `SharedArrayBuffer` is
  available for the splat sorter.

Quest over USB (no HTTPS certificate needed):

```bash
adb reverse tcp:8000 tcp:8000
# open http://127.0.0.1:8000 in the Quest browser
```

For Wi-Fi, put the server behind HTTPS (Caddy/Cloudflare tunnel) because WebXR
requires a secure context.

Performance budget: 512×512 keyframe, ≤ 262,144 splats hard cap, 120k target for the
baked pair and 60k for public uploads, ~3.9 MB per baked `.splat`, 4 frames per
condition. The client loads one frame at a time and coalesces rapid timeline scrubs; it
removes the previous scene rather than keeping four volumes resident on the headset.

## Limitations

- EEG is synthetic. It has realistic spectra and a known schedule, but it is not a
  subject. Do not read the focus/distracted contrast as a clinical result.
- Single-view lifting invents the back of every object. The preview turntable is a
  ±16° arc for that reason; a 360° orbit would expose the sheet.
- Monocular depth is scale-ambiguous. DA-V2 output is mapped into 0.85–6.2 m; ratios
  stay useful, absolute metres do not.
- The procedural keyframe is stylised. Muse Image is the production path.
- The live Meta paths are implemented against the documented wire formats but were not
  exercised without a key in this environment.
- WebXR was validated in desktop Chromium's capability checks, not on a physical Quest.
